1. PROJECT TITLE
Student Attendance Management System (SAMS) — An automated web-based platform designed to
streamline student presence tracking and administrative reporting at ESI-SBA.
2. EXECUTIVE SUMMARY
The Student Attendance Management System (SAMS) is a centralized web platform designed for ESI-SBA to
automate student attendance tracking. It eliminates manual paper recording, accelerates the attendance
logging process during lectures, and provides administrators with automated, accurate absence reports in real
time.
3. PROBLEM STATEMENT
Currently, student attendance at ESI-SBA is recorded manually on paper sheets. This manual process wastes
valuable lecture time, requires significant administrative effort to compile records, and frequently leads to
human data entry errors when calculating student absence rates.
4. PROJECT OBJECTIVES
Reduce Data Entry Errors: Eliminate human mistakes caused by manual paper logging and manual tallying.
Generate Automated Absence Reports: Instantly produce structured, error-free attendance reports for
administration.
Accelerate Attendance Recording: Streamline and speed up the daily attendance logging process during
lectures.

6. PROJECT SCOPE
In-Scope Features: Digital attendance logging, administrative report generation dashboard, and role-based
secure user authentication (Teachers, Students, Administrators).
Excluded Features (Excluded from Version 1.0):
SMS Automated Notifications: Excluded due to strict project budget constraints.
Biometric / Facial Recognition: Excluded due to the tight 6-week development timeframe.
7. FUNCTIONAL AND NON-FUNCTIONAL REQUIREMENTS
The following numbered matrix details the primary functional and non-functional requirements for SAMS:
Req ID Category Requirement Description
FR-01 Functional The system shall record and store attendance status (Present/Absent/Excused)
for each student per session.
FR-02 Functional The system shall automatically generate summary absence reports for
administrative review.
FR-03 Functional The system shall provide secure authentication for teachers, students, and
administrators.
NFR-01 Non-Func. Performance: The system must deliver fast response times (under 2 seconds per
request).
NFR-02 Non-Func. Reliability: The system must ensure zero data loss and maintain high system
availability.
8. PROPOSED METHODOLOGY AND MAIN DEVELOPMENT PHASES
The project follows a structured Agile framework divided into five sequential development phases:
1 Initiation & Requirements Gathering: Define project charter, gather user stories, and refine scope.
2 System Design: Architect database schema, design UI/UX wireframes, and establish API specs.
3 Core Development: Build frontend interfaces and backend attendance processing engines.
4 System Testing: Perform functional unit tests, integration tests, and security evaluations.
5 Deployment & Delivery: Deploy to web server, deliver documentation, and conduct user training.
